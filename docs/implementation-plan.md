# Stasis 实施与验收计划

当前只有设计文档。以下全部为待办，不是已完成能力。

## 推进原则

- 原 `../input-locker` 不改，Rust 版在独立目录与测试事件目录开发。
- 先验证高风险 OS 行为，再扩展 UI 和附属功能。
- 编译通过、模拟测试通过、真机通过分开报告。
- 自动化测试默认不得抓取开发者真实键盘/鼠标、锁屏或写系统策略。
- 不预报固定行数或工期；每一步以验收结果决定是否继续。

## 阶段 0：冻结行为与风险原型

- [ ] 确认设计基线：物理 US 键盘映射、ASCII 密码、Linux 无权限明确失败。
- [ ] 三平台最小 grab/release 原型，脱离 GUI 验证生命周期。
- [ ] Linux 验证锁前按住/锁中释放的按键状态、热插拔与权限不足；决定是否需要 uinput。
- [ ] Windows 验证低级钩子权限、左右 Shift、重复按键、启动/停止消息循环、超时失效的可检测性。
- [ ] macOS 验证 Accessibility、Caps 灯初态、flagsChanged 归一化、tap 禁用及恢复。
- [ ] 常亮原型核实权限、线程归属和释放。

**出口：** 写下每个平台已经验证的行为及无法提供的保证。原型仅在显式授权的真实桌面执行；需有独立
终止/恢复手段和外部时间限制。

## 阶段 1：共享核心与协议

- [ ] 建立单 Cargo package、fmt/clippy/test 和目标特定依赖。
- [ ] 实现共享 Keypad：Caps sticky、重复过滤、左右 Shift、退格、提交、长度上限。
- [ ] 实现配置验证、原子保存、密码存储与显式旧配置导入。
- [ ] 实现协议事件类型、校验、UTC 投影和明确的状态迁移。
- [ ] 实现会话属主、重启恢复、提前解锁和定时结束。
- [ ] 实现 command/ack 认领、防重复与崩溃恢复。
- [ ] 明确并测试物理动作成功但事件写入失败的恢复路径。

**出口：** 不依赖 GUI/系统输入设备的测试可运行；与 aide Go 消费端共享 JSON 样例交叉验证。保留旧
协议语义，不移植旧 `_check_plan` 死路径。

## 阶段 2：引擎与 Linux 可用纵切

- [ ] 单业务线程、命令队列、UI 快照、后端 generation。
- [ ] evdev 后端接入共享 Keypad 和会话核心。
- [ ] 启动确认、超时取消、部分抓取回滚、释放确认、worker 意外退出。
- [ ] UI 面板显示 Stasis、标语、状态、解锁回显和配置入口。
- [ ] 日志滚动、单实例、清理退出。
- [ ] UI 冻结时仍可密码/到期解锁；目录读写缓慢时不能永久阻塞释放。

**出口：** 在有授权的 Linux X11 和 Wayland 桌面分别完成完整锁—Caps×3—密码—解锁流程，并执行下面的
异常用例。未验证的桌面环境明确标注。

## 阶段 3：Windows / macOS 一致性

- [ ] 两个平台只接入规范化输入与资源层，不重写 Keypad/会话逻辑。
- [ ] 所有平台映射都用同一组规范输入轨迹测试。
- [ ] Windows 真机验证，确认权限需求后决定 manifest，不默认整程序提权。
- [ ] macOS 真机验证，包括权限撤销、tap 禁用、Caps 灯状态和窗口失焦。
- [ ] 三端常亮失败/释放行为一致呈现。

**出口：** 三端均有真实桌面测试记录。交叉 `cargo check` 仅算类型检查，不算该平台功能通过。

## 阶段 4：交付与迁移

- [ ] Windows、Linux、macOS 原生 CI 构建及核心测试矩阵。
- [ ] 构建产物、必要运行库、签名/权限引导、配置目录和日志目录文档。
- [ ] Linux 自启动示例；macOS app 包与权限身份验证；Windows 正常退出/升级验证。
- [ ] 切换前停用旧程序与自启动服务，备份配置和事件目录。
- [ ] 使用隔离目录验证 aide command/ack 和 rest-break 端到端，再切正式目录。
- [ ] 准备回退方案，回退时先停 Stasis，保证单一消费者。

**出口：** README 区分已验证平台、已知限制、旧版差异和恢复手段。不以「单二进制」代替安装与权限说
明。

## 可选后续，不阻塞核心版本

- 托盘、自动最小化、全局光标隐藏。
- USB 存储禁用：先设计最小权限与原状态恢复，再实现，默认不启用。
- 任意系统键盘布局/Unicode 密码支持。
- 事件历史归档和增量索引：先测规模；若达到可接受延迟上限，必须在长期运行版本交付前完成。

## 必须留下的回归用例

| 类别 | 用例 |
| --- | --- |
| Keypad | Caps 三次/超时/长按重复/armed 后再按；双 Shift；错密重试；输入上限 |
| 生命周期 | 并发请求序列化；初始化失败；超时后迟到成功；旧代次事件；重复 stop |
| 资源 | 半数设备抓取失败；锁前按住键；锁中松开键；解锁时按住键；鼠标按钮；热拔插 |
| 会话 | 正常到期；立即密码解锁；过期请求；重叠请求；手动锁与会话锁属主 |
| 重启 | 锁中重启；过期后重启；提前解锁后重启；旧 active 与新的物理状态冲突 |
| 时间 | 不同 UTC offset；无效时间；系统时钟前跳/回拨；跨休眠恢复 |
| 文件 | 坏 JSON；合法 JSON 但类型错；过大文件；目录不可读；磁盘满；发布/ack 失败 |
| 动作与记录 | 抓取成功写 locked 失败；释放成功写 unlocked 失败；pending 恢复不得误重锁 |
| command | 重复 ID；旧 processing；执行期间新 command；ack 失败；未知命令 |
| UI | 焦点被抢；最小化；UI 卡顿；退出时仍锁定；密码修改保存失败 |
| 平台 | Windows hook 超时；macOS tap 禁用和权限撤销；Wayland 无设备权限 |

测试层级：纯逻辑单测 → 模拟后端/文件故障集成测试 → 显式 opt-in 真实桌面测试。只在真实桌面层启用
输入抓取，并准备第二设备/SSH 等恢复通道；不能把普通 CI 跑过当作真实输入安全性证明。
